# 媒资审核智能体系统需求说明

## 1. 产品定位

媒资审核智能体系统面向广电机构的老片重播审核，集中管理待审片源、审核依据、机器分析结果、人工复核意见、修改清单和复审报告。

系统使用人脸比对、OCR、ASR 和文本规则匹配，自动定位需要关注的画面、文字和对白；审核员结合原始内容与上下文作出业务判断。机器命中是待核查线索，不等同于违规或最终审核结论。

系统的核心价值是减少审核员在整片中查找、重复观看、整理证据和编写修改清单的时间，同时保留完整的审核依据与历史记录。

## 2. 适用范围

首期支持以下媒资：

- 视频：电影、电视剧单集、纪录片、节目和片段。
- 图片：剧照、海报及其他静态图片。
- 关联字幕：SRT 文件。

首期审核对象如下：

| 对象 | 检查内容 | 处理方式 |
|---|---|---|
| 画面人物 | 已录入人物是否出现、出现位置和参考依据 | 人脸检测与比对，人工确认身份及业务处置 |
| 烧录字幕和画面文字 | 对白字幕、片头片尾、演职员表、标牌、横幅、广告和图片文案 | OCR 识别后按规则匹配 |
| 外挂字幕 | SRT 中的台词、旁白和说明文字 | 解析时间轴后按规则匹配 |
| 对白与旁白 | 视频音轨中的可转写语言内容 | ASR 转写后按规则匹配，可回听原音 |
| 其他画面与内容 | 特定标识、物品、行为、场景、语义和剧情问题 | 首期由人工补充问题并记录依据 |

首期不包含独立音频文件、剧本和其他文档入库、在线剪辑、多机构隔离、批量分集调度、通用工作流设计器、自动播出或发布操作。

审核结论仅对选定的媒资文件版本和审核范围有效，不自动代表整部作品、其他分集或其他版本的结论。

## 3. 用户与权限

| 角色 | 主要职责 |
|---|---|
| 系统管理员 | 创建和停用账号，维护系统配置、存储、备份和算法部署 |
| 资源管理员 | 维护人物、参考照片、文本规则和审核依据 |
| 审核员 | 创建和处理任务，查看证据，记录问题，提交结论和复审结果 |
| 只读用户 | 查看授权的媒资、任务和报告 |

一个用户可以拥有多个角色。每个任务有一名负责人，负责人拥有编辑和提交权限，可将任务转交给另一名有权限的审核员。只读用户不能修改任务、下载原文件、下载参考图或导出报告。

权限检查覆盖页面、接口、文件预览、下载和导出。账号停用后，现有会话失效，历史记录仍保留责任人信息。

## 4. 核心业务对象

| 对象 | 说明 |
|---|---|
| 媒资 | 待审的视频或图片及其基本资料 |
| 媒资版本 | 不可变的文件版本；修改版作为新版本保存 |
| 关联字幕 | 与视频关联的 SRT 文件，独立保存版本 |
| 人物档案 | 人物名称、别名、分组、核查说明、依据和多张参考照片 |
| 文本规则 | 词语或短语、分类、匹配方式、例外、说明和业务依据 |
| 审核任务 | 对一个媒资版本执行的一次审核，固定输入、资源、参数和负责人 |
| 分析流程 | 人物比对、SRT、OCR、ASR 等固定处理流程 |
| 原始结果 | 人脸检测、OCR 文字、ASR 转写、规则命中等机器输出 |
| 复核事件 | 供审核员一次查看和处置的一组相关线索 |
| 审核问题 | 人工确认需要修改或不通过的事项，可关联多个证据 |
| 修改清单 | 审核问题的对外交付视图 |
| 审核报告 | 审核范围、依据、问题、结论和人员信息的固定快照 |

## 5. 业务流程

1. 上传或选择媒资，并关联可用字幕文件。
2. 系统解析文件、生成预览和基本属性，确认媒资可用。
3. 创建审核任务，选择人物核查、文本来源、人物范围、规则范围和负责人。
4. 系统执行所选分析流程，生成机器线索、证据和自动关联事件。
5. 审核员查看事件、播放上下文、确认或补充问题，并填写修改要求。
6. 审核员确认审核覆盖范围，提交通过、修改后复审或不通过结论。
7. 系统生成修改清单和正式报告。
8. 上传修改版后创建关联复审任务，验证旧问题并检查修改版中的新问题。

## 6. 功能需求

### 6.1 媒资管理

- 支持上传 MP4、JPG、PNG 和关联 SRT 文件；支持格式、编码、文件大小由部署配置明确。
- 上传时校验真实文件类型、大小和可解析性，提取时长、分辨率、帧率、音轨、文件指纹等信息。
- 自动生成视频封面或图片缩略图，记录解析状态：处理中、可用、失败。
- 不可用媒资不能创建审核任务，失败时应展示具体原因并支持重新上传或重新解析。
- 媒资列表支持按名称、类型、标签、上传时间和审核状态检索。
- 视频支持播放、暂停、倍速和时间跳转；图片支持缩放与区域查看。
- 原文件和已被任务引用的字幕不能被覆盖。上传修改版生成新的媒资版本，旧任务继续指向原文件。
- 支持归档媒资；首期不在产品界面中直接物理删除被任务引用的文件。

### 6.2 人物资源库

- 支持人物新增、编辑、检索、分组、启用和停用。
- 每个人物保存姓名、别名、核查说明、业务依据、维护责任人和参考照片。
- 同一人物可维护多张参考照片，首期要求每张参考图仅包含一张清晰人脸；无人脸或多人脸图片提示重新上传裁好的图片。
- 任务创建时必须显式选择人物或人物分组，不默认对全库执行。
- 人物资源修改记录操作者、时间和变更内容。任务创建后保存所用人物、参考图和说明快照，后续修改不影响历史任务。

### 6.3 文本规则库

- 每条规则包含词语或短语、分类、说明、业务依据、启停状态和可选例外短语。
- 支持包含匹配和精确匹配。首期默认采用包含匹配。
- 支持统一空格和大小写处理，保存原文命中位置；不做同音、语义或任意脚本扩展。
- 例外短语只排除其完整覆盖的命中位置，不影响其他位置的命中。
- 提供规则测试入口，输入文本后展示标准化结果、命中位置和例外效果。
- 规则修改记录操作者、时间和变更内容。任务创建后固定规则、例外和说明快照。
- 首期在一条 SRT、一个 OCR 文本段或一个 ASR 段内匹配，不跨来源拼接或跨段匹配。

### 6.4 审核任务

- 从媒资详情或任务列表创建任务，选择待审媒资版本、审核负责人和审核范围。
- 人物核查可独立选择。文本审核支持同时选择 SRT、OCR、ASR；图片仅支持 OCR。
- SRT 选择一个关联字幕文件；ASR 选择一个视频音轨；OCR 选择全画面或一个矩形区域。
- 提交前展示实际执行范围，并检查片源、字幕、音轨、模型、人物库和规则库是否可用。
- 任务固定保存媒资版本、字幕版本、音轨、OCR 区域、人物、规则、模型和分析参数。
- 后台执行人物、SRT、OCR、ASR 四条固定流程，限制并发，其余任务排队。
- 任务详情展示阶段、进度或已处理时长、失败原因和可重试项。
- 已成功流程不重复运行；失败或中断流程可以重试，失败尝试的局部结果不混入当前结果。
- 运行中的任务可取消。排队任务直接取消，运行任务在停止后收敛为已取消；取消后的迟到结果不得覆盖最终状态。
- 服务重启后，未完成流程标为中断可重试，已成功结果保留，已取消任务不自动恢复。

### 6.5 自动分析与证据

#### 人物核查

- 对视频采样帧或图片检测人脸，并与选定人物的多张参考图比对。
- 将同一人物邻近时间的检测结果聚合为出现片段。
- 每条人物线索展示参考图、关键帧、人脸框、时间位置、匹配分数和核查说明。
- 多个候选人物相近时保留歧义，不强制确定唯一身份。
- 无命中时展示已检查时间范围和采样策略，不自动产生通过结论。

#### 文本提取与匹配

- SRT 解析文本、序号和时间轴，校验编码、时间格式和越界问题；可保存统一时间偏移。
- OCR 保存原图或关键帧、文字框、识别文本和时间位置；连续重复文字可以在同一来源内合并，原始定位仍可查看。
- ASR 保存转写分段和时间位置，支持回听原音与查看前后文本；不承诺逐字时间精度。
- 每个文本来源分别执行规则匹配，展示原文、命中高亮、上下文、规则依据和位置。
- 系统区分提取失败、成功但未识别到文本、有文本但无规则命中。

#### 多来源自动关联

- 所有选定来源分析成功后，系统自动将同一处文本内容的相关命中组织为复核事件。
- 自动关联使用确定性条件：同一任务、时间重叠或在配置容差内、标准化文本及邻近上下文相似。
- 同一文本位置命中的多条规则可以归入同一事件。相同关键词但位置不同、上下文明显不同或关联不明确的结果保持独立。
- 同一时间的不同文字区域不能仅因时间重叠自动合并。
- 每个事件展示来源数量、位置数量、全部命中规则和文字差异；审核员可展开查看每个来源的完整证据。
- 自动关联不删除原始命中、不自动创建业务问题，也不将人物线索与同时间文本自动视为同一事件。
- 审核员可以拆分误关联事件或人工合并漏关联事件。涉及成员重新回到待复核状态，原始证据和操作记录保留。

### 6.6 审核工作台

- 统一工作台展示播放器或图片、复核事件、人物线索、问题清单和审核范围摘要。
- 事件卡片默认展示关注原因、关键证据、命中句或人物对照、时间位置和处理操作；完整规则、模型参数和全部原文按需展开。
- 点击事件后，视频自动定位到事件前的上下文位置，支持播放当前片段、重播、前后扩展、跳转到下一条待处理事件。
- 显示同一事件涉及的位置、来源、命中原因和文字差异。未展开存在差异的证据摘要时，不能对整组统一处置。
- 审核员可对每个原因或整个事件选择：无需处理、需要修改、不通过、暂不能判断。
- “无需处理”可选择识别错误、上下文可接受等原因。机器是否正确不是每条线索的必填项。
- “需要修改”或“不通过”时，系统自动带入文件版本、位置、原文、证据和规则依据，审核员补充或修改处置说明。
- 提供常用修改短语，允许直接编辑；不建设独立模板管理功能。
- 同一事件可以形成多个审核问题；多个来源证据也可以关联到同一个问题。
- 审核员可以人工补充机器遗漏或不在自动范围内的问题。人工问题和机器问题同样影响最终结论。
- OCR 和 ASR 校正文与机器原文并列保存。审核员可使用当前任务中的规则快照进行局部规则测试，并将测试命中转为人工问题；测试不改变机器结果、已有问题或统计数据。
- 分析期间允许审核员记录带时间或图片位置的草稿。草稿不属于正式复核意见，分析完成后可转为问题、并入已有问题或明确忽略。
- 系统保存当前筛选、播放位置、正在查看的事件和未提交编辑内容。支持播放、重播、上一条和下一条待办的键盘操作；输入文本时不抢占快捷键。
- 每个任务只有负责人可以编辑和提交。转交后立即撤销原负责人编辑权，旧页面不能覆盖新负责人数据。

### 6.7 问题、结论与报告

- 每个审核问题保存类别、描述、时间或区域、证据、业务依据、修改要求和处置结果。
- 有效问题只能标记为需修改或不通过；撤销问题必须填写原因并保留操作记录。
- 需要处理的线索必须关联有效问题；被撤销的问题不能作为提交依据。
- 正式提交前，全部所选流程和自动关联必须成功，所有线索和命中原因必须处理完毕，不存在暂不能判断、未处理草稿或未保存修改。
- 审核员必须确认人物、文本来源、音轨、OCR 区域和采样范围等实际覆盖情况。
- 存在不通过问题时，任务结论为不通过；不存在不通过问题但存在需修改问题时，结论为修改后复审；其他情况可以通过。
- 修改清单作为主要交付物，包含文件版本、问题编号、位置、问题内容、证据、依据、修改要求、当前处置和复审状态。
- 正式报告由同一份问题数据生成，包含审核范围、资源与模型标识、问题、结论、审核人员和时间，支持打印与 JSON 导出。
- 正式报告提交后锁定。发现错误时创建关联更正任务，保留原报告及关联关系。
- 失败、取消、终止或未完成任务只能导出标明状态的阶段结果，不能生成正式通过报告。

### 6.8 修改版复审

- 上传修改版后创建新任务，并关联原报告和完整旧问题清单。
- 修改版重新执行所选分析流程。旧时间位置只作为参考，不自动映射到新版本。
- 每个旧问题标记为待验证、已解决、未解决或无法判断，并记录修改版位置或删除确认依据。
- 待验证和无法判断阻止正式提交；未解决问题沿用原有处置并影响复审结论。
- 复审通过要求所有旧问题已解决、本次任务无有效问题，并满足正式提交条件。

### 6.9 运行保障与审计

- 数据库、原始文件、证据文件和报告持久化保存。
- 资源维护、任务转交、复核意见、问题撤销、报告提交和权限变更记录操作者、时间、对象和变更内容。
- 提供备份与恢复操作说明，并完成一次包含文件和数据库的恢复验证。
- 存储不足、模型不可用、字幕异常、音轨缺失和文件损坏应显示用户可理解的错误信息。
- 系统参数、模型部署、备份策略和存储保留由部署配置和运维流程管理，不要求首期建设完整管理后台。

## 7. 状态与提交规则

| 对象 | 状态 |
|---|---|
| 分析流程 | 排队、运行、成功、失败、中断、已取消 |
| 任务分析 | 排队、运行、成功、部分失败、失败、取消中、已取消 |
| 人工复核 | 未开始、进行中、已提交、已终止 |
| 线索 | 待复核、已处理、暂不能判断 |
| 审核问题 | 有效、已撤销 |
| 整改验证 | 待验证、已解决、未解决、无法判断 |

全部选定流程及自动关联成功后，任务才进入正式复核。分析期间只允许保存草稿。存在待处理线索、暂不能判断、未处理草稿、未保存编辑或未确认覆盖范围时，不允许提交正式结论。

原始机器命中数、复核事件数、有效问题数和整改已解决数分别统计。自动关联不减少原始命中数。正式报告固定提交时的范围、事件、证据、问题和统计值。

## 8. 页面范围

1. 登录和用户管理。
2. 媒资列表、上传和媒资详情。
3. 人物资源库和文本规则库。
4. 任务列表、任务创建和运行详情。
5. 审核工作台，修改版任务增加旧问题验证区。
6. 修改清单和审核报告页面。

图片复用审核工作台，隐藏时间轴、音轨和视频播放功能。

## 9. 验收要求

| 编号 | 场景 | 验收结果 |
|---|---|---|
| AC-01 | 上传正常和损坏的视频、图片 | 可用文件能预览并创建任务，异常文件明确拒绝并说明原因 |
| AC-02 | 上传修改版、修改人物或规则后查看旧任务 | 历史任务仍显示原文件、依据和报告，新任务可使用新版本或新资料 |
| AC-03 | 创建人物单项任务和 SRT、OCR、ASR 多来源任务 | 所选范围正确执行，人物任务不要求字幕，多来源均可查看结果与证据 |
| AC-04 | 无音轨、字幕异常、无文本和无命中 | 状态准确区分，不自动通过 |
| AC-05 | 单个流程失败、重试、中断和取消 | 成功结果保留，失败结果不混入，取消结果不被迟到写入覆盖 |
| AC-06 | 人物、OCR、SRT、ASR 证据定位 | 可回看画面或原音上下文，人物相似度不会直接生成业务问题 |
| AC-07 | 同一内容被多个来源和规则命中 | 自动形成复核事件，所有来源和原因可查看并分别处置，系统不隐藏文字差异 |
| AC-08 | 相同关键词出现在不同位置，或同时间有不同文字区域 | 不发生错误合并，独立内容保持独立事件 |
| AC-09 | 拆分误关联事件或合并漏关联事件 | 原始证据不丢失，相关成员回到待复核，未重新处置前不能提交 |
| AC-10 | 事件上下文播放、键盘操作和离开后返回 | 上下文不越界，播放位置、筛选和未提交内容正确恢复 |
| AC-11 | 校正文和局部规则测试 | 原机器结果不改变，测试使用任务规则快照，采纳内容明确标记为人工结果 |
| AC-12 | 分析期间保存草稿，分析完成后采纳或忽略 | 草稿不形成正式意见，不自动关联事件，未处理草稿阻止提交 |
| AC-13 | 存在未处理、暂不能判断、需修改、不通过或人工补充问题 | 提交条件和结论计算正确，服务端拒绝绕过 |
| AC-14 | 从事件生成问题、修改清单和报告 | 位置、证据和依据自动带入，问题、修改清单和报告数据一致 |
| AC-15 | 修改版复审 | 旧问题未解决或无法判断时不能通过；所有旧问题解决且本次无问题时可以通过 |
| AC-16 | 转交任务、旧页面编辑、账号停用和越权文件访问 | 编辑权即时生效，旧页面无法覆盖，无权限请求被拒绝 |
| AC-17 | 从备份恢复文件和数据库 | 历史媒资、任务、问题、报告和证据均可读取 |

## 10. 效果与性能验证

在建设大量管理功能前，使用具有代表性的老片片段和至少一个完整片源验证人物比对、OCR、ASR、规则匹配和多来源自动关联。

验证应记录样本、片源属性、模型和参数、硬件、分析耗时、机器命中、误报、漏报、定位误差、自动关联误合并和漏合并，以及审核员完成相同范围审核的总时间。

验收样本应独立于调参样本。评估重点是：在相同审核范围和质量要求下，系统是否减少总人工审核时间，而非只减少点击次数或复核事件数量。

具体支持语言、编码、片长、文件大小、并发数、硬件配置和算法合格指标，在效果验证后按实际数据确定。

## 11. 后续扩展

后续能力包括内嵌字幕提取、跨行匹配、批量导入、断点续传、自动转码、跨任务缓存、分布式调度、专项画面识别、多审核员协作、资源发布审批和复杂权限管理。

LLM 可以作为独立审核能力，用于语义辅助、隐喻和谐音提示、剧情研判、依据检索和报告草稿。LLM 输出必须关联原始证据、输入范围、模型标识和人工确认结果。正式审核结论仍由有权限的审核员提交。
