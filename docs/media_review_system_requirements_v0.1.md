# 媒资智能审核系统功能需求文档

版本：V0.1（产品讨论稿）

日期：2026-09-16

首期定位：面向广电视听内容审核场景，建设可独立运行的媒资管理与辅助审核系统。

## 1. 建设目标与基本思路

系统集中管理电影、节目片段、其他视频及图片，支持用户选择审核类别，自动分析内容、定位疑似问题，并由审核人员结合原始画面和上下文形成最终结论。

首期建设四部分：

1. **媒资库**：解决“待审内容在哪里、是什么、如何管理”。
2. **审核资源库**：维护“依据哪些人物参考资料和文本规则进行核查”。
3. **审核工作台**：首先提供人物人脸比对和字幕文本审核两类能力，分别运行、统一展示。
4. **系统管理**：提供登录、用户权限、任务持久化、文件存储与操作记录，让原型成为可持续使用的独立系统。

整体业务流程：

> 上传媒资 → 文件解析与预览 → 创建审核任务 → 选择审核项目及资源库版本 → 自动分析 → 查看画面和文本证据 → 人工复核 → 形成结论及报告 → 归档或重新审核。

本文中的“媒资”指媒体资产；“命中”指机器产生的核查线索，不直接等同于违规。人物比对只核查与已录入参考人物的相似关系，不根据外貌推断政治立场、涉案状态等属性。需要核查的原因由有权限的人员依据业务材料维护，最终内容处置由人工决定。

## 2. 首期范围

| 模块 | 首期必备 | 后续扩展 |
|---|---|---|
| 媒资管理 | 视频、图片上传，信息编辑，分类标签，搜索，预览，审核历史 | 大文件断点续传、批量导入、复杂节目层级、外部媒资系统对接 |
| 人物资源库 | 人物档案、多张参考照片、分组、核查说明、启停与版本记录 | 批量维护、参考图质量评分、多人协同维护 |
| 人脸审核 | 对选定人物库进行比对，按人物及出现片段展示，关键帧定位 | 更完善的跨镜头关联、性能优化 |
| 字幕审核 | 外挂 SRT 字幕导入；视频画面与图片 OCR；关键词和短语规则匹配 | 内嵌字幕轨提取、语音转写、语境和隐喻辅助分析 |
| 人工复核 | 逐条处置、补充线索、审核项结论、任务结论、报告导出 | 多级审批、申诉、复审派单 |
| 用户与系统 | 账号登录、角色权限、任务队列、持久化、操作日志 | 单点登录、多组织隔离、分布式调度 |

默认首期服务一个机构内部的小规模审核团队，以浏览器访问。任务首期一次对应一个媒资文件，可勾选一个或多个审核项目。电影分集、完整节目编排、在线剪辑和内容发布不纳入首期。

## 3. 用户与权限

| 角色 | 主要职责与权限 |
|---|---|
| 系统管理员 | 维护账号与角色、系统参数、存储及运行状态；业务审核权限另行授予 |
| 资源管理员 | 管理媒资资料、人物库、关键词库及规则版本；默认不具备最终审核权限 |
| 审核员 | 创建任务、查看授权媒资、核查证据、修改复核结果、提交最终结论 |
| 只读用户 | 查看授权媒资及已完成报告，不能修改资源或审核结论 |

允许一人兼任多个角色。首期以机构内统一资源空间为默认方案，人物参考照片、原始文件下载、报告导出和资源删除分别控制权限。权限校验覆盖页面、接口及文件访问。

## 4. 媒资库

### 4.1 媒资入库

- 首期支持上传单个视频或图片，并上传或关联外挂字幕文件；视频格式优先覆盖 MP4，图片覆盖 JPG、PNG。
- 入库前检查文件类型、大小及可解析性；不支持的文件明确提示原因。
- 上传后自动提取可获得的文件信息：时长、分辨率、文件大小、格式等；生成视频封面或图片缩略图。
- 媒资使用唯一编号。相同文件再次上传时提示可能重复，用户可复用已有媒资或明确创建新记录。
- 文件准备状态独立记录为“处理中、可用、处理失败”。只有可用媒资可以发起审核。
- 解析失败时保留错误原因，支持重试或重新上传。

### 4.2 媒资信息

| 字段 | 说明 |
|---|---|
| 媒资编号、名称 | 编号自动生成，名称可编辑 |
| 媒资类型 | 视频、图片；外挂字幕作为关联文件 |
| 业务分类 | 电影、电视剧、纪录片、节目片段、宣传片、其他等，可配置 |
| 标签与简介 | 用于检索、分组和理解内容 |
| 来源与使用说明 | 来源单位或渠道、相关授权说明，按业务需要填写 |
| 文件属性 | 格式、大小、时长、分辨率、文件指纹等 |
| 创建信息 | 上传人、上传时间、最后修改时间 |
| 审核概况 | 最新任务、运行状态、最新已完成结论及历史任务数量 |

名称修改仅修改资料字段。替换实际文件需生成新的媒资版本，旧任务仍关联原文件，保证历史证据可回看。

### 4.3 列表与详情

媒资列表支持按名称、类型、分类、标签、上传时间和审核情况筛选；支持列表或缩略图展示。主要操作为查看、编辑、发起审核和归档。

视频详情页提供播放器、基本信息、关联字幕及审核历史；图片详情页提供放大预览、基本信息及历史结果。点击历史任务可进入其结果页。

首期优先使用归档隐藏不再使用的媒资。已被任务引用的原始文件不能直接删除；彻底清理由管理员按保留策略处理，并明确是否影响历史证据与报告。

## 5. 审核资源库

资源库与待审媒资库分开：前者保存核查依据，后者保存被审核内容。

### 5.1 人物资源库

每个人物建立独立档案，包含人物编号、姓名、别名、分组、参考照片、核查说明、依据来源、有效期、启用状态及维护记录。姓名相同的人物以编号区分。

一个人物可配置多张已确认身份的参考照片，用于覆盖不同年龄、角度与外观。上传参考图后检查是否可检测到人脸；无人脸时提示更换，多人脸时要求选择并确认目标，避免错误入库。

支持人物新增、编辑、搜索、分组、启用及停用。任务可以选择整个人物分组或指定人物，不默认对全部档案无差别运行。已停用或已过有效期的人物不进入新任务，历史结果仍保留原有依据。

涉及特殊核查要求的档案需记录业务依据及维护责任人，避免将身份匹配本身视为问题判断。参考照片和特征仅供授权的审核业务使用。

### 5.2 关键词与规则库

首期按业务建立可配置规则分类，例如政治表述核查、暴力及不当内容提示、广告宣传用语核查等；具体词条与适用标准由业务人员提供。

每条规则包括：规则编号、关键词或短语、匹配方式、分类、提示级别、说明、适用范围、例外词组、启用状态及维护记录。

首期提供精确匹配、包含匹配及完整例外短语配置，不向普通用户开放任意脚本规则。匹配前可统一空格、大小写等，并保留原始文本用于证据回看。具体采用哪些标准化操作由规则配置明确。

例外仅作用于其覆盖的词语位置，不能屏蔽整段中的其他命中。后台测试入口允许输入一段文字，预览命中位置、命中规则与例外效果，再发布生效。

### 5.3 版本与生效

人物库和规则库的修改保存维护记录。发布后生成可追溯版本，任务创建时锁定所选版本、算法版本及关键参数。资源库更新不改变已完成任务；需要应用新规则时重新创建任务，并关联原任务。

## 6. 审核任务与运行流程

### 6.1 创建任务

用户从媒资详情或任务中心发起审核，填写任务名称，选择：

- 待审媒资及文件版本；
- 审核项目：人物比对、字幕文本审核，可单选或同时选择；
- 人物分组或指定人物、文本规则分类及对应版本；
- 字幕来源：已有外挂字幕或画面 OCR；
- 审核负责人，默认创建人，也可指定有权限的审核员。

普通用户使用预设分析参数；人脸阈值、视频采样策略等由管理员维护。提交前检查文件是否可用、参考库是否为空、字幕是否有效及对应分析能力是否可用，并展示预计执行项目。

### 6.2 状态与调度

任务运行状态、人工复核状态和最终结论分别存储，避免混为一个“审核状态”。

| 维度 | 状态示例 |
|---|---|
| 自动分析任务 | 排队中、处理中、分析完成、部分失败、失败、已取消 |
| 单个审核项目 | 待执行、执行中、成功、失败、已取消 |
| 人工复核 | 未开始、复核中、已完成 |
| 最终业务结论 | 通过、需修改、不通过；未提交时为空 |

两类审核分别执行并汇总到同一任务。某一项失败时，已成功项目的结果继续可查看，但任务不能按正常流程提交“全部通过”。失败项支持单独重试，保留尝试记录，以最后一次成功尝试作为当前结果，避免重复累计命中。

任务列表展示执行阶段、可确定的进度、提交时间、负责人、各项结果和异常原因。系统限制同时运行数量，其余排队。用户可取消未完成任务；取消或失败后的部分结果需明确标识为不完整。

媒资、任务、证据和复核结果持久化保存。服务重启后，已完成数据不丢失，未完成任务明确恢复执行或进入可重试状态，不能永久显示处理中。

## 7. 审核类别一：人物人脸比对

### 7.1 处理逻辑

1. 读取所选人物档案与参考图。
2. 对视频按配置采样并检测人脸；图片直接检测。
3. 将检测到的人脸与参考人物进行相似度比对。
4. 根据阈值和画面质量产生候选线索。
5. 将同一人物连续或邻近的命中画面聚合成出现片段，生成代表性关键帧。
6. 将疑似人物、片段位置及参考图送入人工复核。

不同人物候选相近时保留歧义，不强行确定唯一身份。相似度显示为匹配分数，不解释为“身份正确的概率”。模糊、小人脸、侧脸等低质量画面提示复核。

### 7.2 结果内容

每条线索至少包括：候选人物、所属分组、核查说明、匹配分数、参考照片、媒资关键帧、人脸框及复核状态。

视频额外显示出现起止时间、代表帧时间、累计命中帧数和跳转播放按钮；图片显示命中区域和放大查看入口。视频片段时间是基于检测及聚合得到的定位范围，不宣称精确覆盖人物出现的每一帧。

支持按人物、提示级别、时间和复核状态筛选。未命中显示“本次分析未发现匹配线索”，并展示采样范围和参数，便于理解检测覆盖程度。

### 7.3 人工处置

审核员对每条线索选择“确认匹配、非该人物、无法判断”，并独立记录内容处置意见，如“无需处理、需要修改、提交进一步复核”。确认匹配不会自动生成不通过结论。

## 8. 审核类别二：字幕与画面文字审核

### 8.1 文本来源

首期支持三条入口：

| 入口 | 处理方式 | 证据定位 |
|---|---|---|
| 视频外挂字幕 | 读取关联 SRT 文件中的文本及时间轴 | 字幕行、起止时间与对应视频画面 |
| 视频画面文字 | 对采样帧执行 OCR，支持设置字幕识别区域，并合并连续重复文本 | 原始关键帧、文本区域与时间范围 |
| 图片文字 | 对图片执行 OCR | 原图、文字框与识别文本 |

创建任务时明确采用哪个来源；若同时采用多个来源，各自保留证据并对重复线索建立关联，不重复计算为多个独立问题。外挂字幕的内容可能与实际画面不同，界面需明确标注来源。

画面 OCR 可用于烧录字幕，也可检查标题、标语等可见文字；只检查字幕区域时，应明确提示覆盖范围。语音转写属于后续独立文本来源，不能被视为视频字幕的等价替代。

### 8.2 处理逻辑

1. 提取文本及对应时间或空间位置。
2. 合并重复 OCR 文本，保留原始识别结果和定位关系。
3. 按选定规则执行关键词或短语匹配，应用例外规则。
4. 为命中生成上下文、规则说明、提示级别和原始画面证据。
5. 将结果提交人工核查。

OCR 可能识别错误，审核员可录入校正文本。系统同时保留原文、校正文和修改人，并允许对校正后的文本重新匹配，记录新的匹配结果。不得用校正文覆盖原始证据。

外挂字幕无法解析应报告失败；OCR 成功执行但未识别到文字时显示“未提取到可审核文本”，要求人工确认覆盖情况；有文本但没有规则命中时才显示“未发现文本规则命中”。

### 8.3 结果内容与处置

每条线索展示原始文本、命中高亮、前后上下文、命中规则、分类、提示级别、来源、视频时间或图片位置及关键帧。

人工处置包括“确认需处理、上下文可接受、识别错误、无法判断”，需要时填写依据与修改建议。规则命中本身不直接构成最终业务结论。

### 8.4 后续语义分析

后续增加独立的“语义辅助审核”项目，用于理解上下文、隐喻、谐音等。结果需关联原文片段、上下文、解释及模型版本，并进入人工复核。首期仅预留接入位置，不把语义或隐喻识别列为交付能力。

## 9. 统一结果工作台与人工复核

### 9.1 页面布局

- **顶部概览**：媒资、任务状态、所选审核项、各项分析完成情况、待复核数量及最终结论。
- **左侧预览**：视频播放器或图片预览，支持画面放大及证据框显示。
- **中部或下方时间轴**：按类别标记人物片段和文本命中点；点击后定位并播放前后上下文。
- **右侧线索列表与详情**：按“全部、人物、文本”切换，查看参考资料、依据及人工处置。
- **底部提交区域**：各审核项结论、整体结论、修改要求和报告入口。

保留逐条复核的操作记录。首期不提供不经查看的一键全量确认。允许审核员手动补充机器遗漏的线索，填写时间或图片位置、类别、描述及证据，并标记来源为人工。

### 9.2 结论形成条件

每个已选择的审核项均需分析成功、线索处置完成、审核员确认覆盖情况，才能进入最终结论提交。没有线索仍需人工确认，不能自动完成整个审核任务。

存在“无法判断”的线索时保留为待复核，补充资料后继续处理。整体通过要求各审核项均通过；任何项目要求修改时，整体不能通过；存在不通过项目时，整体结论为不通过。

任务负责人提交最终结论，注明审核说明及必要的修改要求。提交后原记录锁定，更正时创建关联的复核记录或新任务，保留原结论及更正原因。

### 9.3 报告与归档

首期提供可打印的报告页面和结构化 JSON 导出。报告包括媒资信息、文件版本、审核范围、资源与算法版本、各审核项结果、证据图片或位置、人工意见、最终结论、审核人及时间。

报告区分机器原始命中数、确认需处理数和误报数。未完成、失败或取消的任务只能生成明确标识的阶段结果，不能显示为正式通过报告。

## 11. 独立系统运行要求

### 11.1 登录与用户管理

账号由管理员创建，支持修改密码、重置密码、停用账号和退出登录。首期不开放注册。账号停用后不能继续访问，但历史审核记录保留人员标识。

### 11.2 基础运行组成

系统包括浏览器界面、业务服务、后台分析任务、持久化数据库及文件存储。视频分析在后台执行，刷新页面或退出浏览器不影响任务。

首期可按单节点部署，限制任务并发。算法能力通过统一的审核项目接口接入，接收媒资和配置，返回状态、线索、证据及错误信息；新增类别时复用现有任务、权限和复核界面。

### 11.3 数据关系

| 核心对象 | 主要关联 |
|---|---|
| 媒资及文件版本 | 关联原文件、封面、字幕及多次审核任务 |
| 人物及参考图 | 关联人物分组、核查说明及资源版本 |
| 文本规则 | 关联规则分类、例外及发布版本 |
| 审核任务 | 固定媒资版本、资源版本、创建人及负责人 |
| 审核项目与执行尝试 | 分别记录人物、文本等项目的状态和重试历史 |
| 线索与证据 | 关联项目、时间或区域、命中依据及证据文件 |
| 复核记录与最终报告 | 关联处置人员、修改历史及任务结论 |

### 11.4 稳定性与数据管理

- 上传限制、视频采样策略、并发数及超时可配置；硬件与测试集确定后再约定具体性能指标。
- 分析异常显示可理解的原因，如文件损坏、模型不可用、字幕格式错误或存储不足。
- 文件和数据库具备备份与恢复方案，并实际验证一次恢复；保留期限由部署方配置。
- 人物参考图、特征和审核证据按权限读取；日志避免记录完整特征数据、密码等内容。
- 资源发布、审核处置、最终结论提交、权限调整及删除操作记录操作者和时间。

## 12. 与现有原型的关系

根据当前仓库 README，项目已具备单视频与单个人物参考图的人脸检索、异步进度、按时间聚合线索、证据帧及静态 Web 界面；任务状态目前保存在进程内。

因此首期开发可以复用现有人脸分析与证据输出能力，但需要新增：

1. 媒资持久化入库、人物档案与多参考图管理。
2. 多人物比对及审核项目统一的数据结构。
3. 数据库任务记录、后台队列、重试与重启恢复。
4. 字幕导入、OCR、规则匹配与文本证据定位。
5. 账号权限、人工复核、结论锁定和报告归档。

原型中的“自动确认”在产品界面中调整为“高相似度线索”等机器判定提示，避免与人工确认或最终审核通过混淆。本节为需求差距判断，不代表上述新增能力已经实现。

## 13. 首期验收场景

| 场景 | 验收预期 |
|---|---|
| 视频、图片正常入库 | 能查看封面或缩略图、基本信息、原始内容并发起任务 |
| 文件异常 | 明确显示失败原因，不能对不可用文件发起任务 |
| 人物库管理 | 同一人物支持多参考图；无脸或多脸参考图有明确处理要求 |
| 视频人物命中 | 可查看候选人物与关键帧，点击时间定位原视频，记录匹配和业务处置 |
| 图片人物命中 | 能查看人脸框、参考图并进行人工判断 |
| 字幕词条命中 | SRT 文本可匹配规则并定位对应视频时间 |
| OCR 命中 | 视频与图片可展示识别文字、命中内容及原始画面区域 |
| 无文本或无命中 | 界面区分提取失败、没有文字、没有规则命中，且不自动出具通过结论 |
| 多审核项运行 | 两项分别呈现状态；其中一项失败不会丢失另一项结果，也不能整体通过 |
| 重试及取消 | 保留尝试记录、不重复累计线索；取消结果明确标识为不完整 |
| 人工补充和更正 | 可补充漏检线索；文字校正保留原始证据和修改历史 |
| 权限与留痕 | 只读用户不能修改；无权限不能读取参考图或导出；关键操作可追溯 |
| 重启恢复 | 历史媒资、结果、证据和复核记录仍可读取；中断任务可以恢复或重试 |
| 版本追溯 | 更新人物库或词库后，旧任务仍显示执行时依据，新任务使用新版本 |
| 完整审核闭环 | 全部所选项目完成并复核后，可提交结论、查看和导出归档报告 |

算法效果单独验收：准备人工标注的视频、图片、人物参考图及字幕样例，包含命中、未命中、模糊人脸、重复字幕和上下文可接受等情况。分别统计人物比对的误报与漏报、文本提取正确性、规则命中及时间定位误差。具体指标与性能目标在测试集、采样策略和部署硬件确定后约定，不以单一样片作为整体准确率依据。

## 14. 建议实施顺序与待确认项

**第一阶段：先跑通人物审核闭环。** 完成登录、媒资入库、人物库、任务持久化、人脸结果页、人工复核和报告。

**第二阶段：完成首期双类别审核。** 接入外挂字幕、画面 OCR、规则库、文本复核和统一任务汇总，同时验证权限、重试、备份恢复及首期验收场景。第一阶段仅作为内部里程碑，第二阶段完成后才算满足本首期范围。

**后续阶段：提升覆盖与效率。** 根据实际数据接入内嵌字幕、语音转写、语义审核、大文件上传和批量任务。

后续细化时优先确认以下业务条件，当前可先按本文默认方案进行页面设计：

- 常见视频时长、单文件大小、每日任务量与同时使用人数，用于确定上传及并发配置。
- 人物库规模、参考资料来源、维护责任人及有效期要求。
- 现有字幕来源，以及业务更关注字幕区域还是全部画面文字。
- 首批文本规则分类、例外场景及最终结论用语。
- 部署网络与硬件条件、文件保留期限及备份位置。
- 是否需要组织间隔离、双人复核或专门的最终审批角色；当前首期默认单机构、单审核员提交。
