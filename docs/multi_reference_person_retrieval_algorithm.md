# 多参考图人物检索与审核事件算法设计

## 1. 目标与边界

本算法用于在本地媒资中检索审核对象库中的人物，并将帧级相似度转化为可复核的“人物—媒资—时间段”证据事件。目标是减少人工浏览整片的工作量，而非用单张截图或单一模型分数自动作出审核结论。

适用范围：本地存储的视频、节目、片段；已人工核验身份的人物参考图；人物出镜的候选发现、归并、排序与人工复核。

不适用范围：用人脸分数判定人物行为、剧情含义或审核结论；将演员表当作逐帧标注；把随机跳帧失败当作人物未出现。

系统输出必须区分以下状态：

| 状态 | 含义 | 是否进入人工审核 |
| --- | --- | --- |
| 未观察到 | 在已覆盖范围内没有达到候选条件 | 否；保留覆盖信息 |
| 候选 | 有单帧或短轨迹的召回证据 | 是 |
| 已确认 | 多项确定性证据满足确认规则 | 是；人工可抽查或确认 |
| 身份歧义 | 与多个对象分数接近，无法安全归属 | 是，按歧义处理 |
| 数据质量不足 | 解码、清晰度、遮挡或人脸过小导致结论不可靠 | 是，提示补扫或人工浏览 |

“候选”和“已确认”是不同产品状态：候选服务于不漏，确认服务于少打扰人；两者不能共用一个全局阈值。

## 2. 核心原则

1. **更多参考图不等于更好。** 重复的自拍、同一镜头连拍或低质量图会放大偏差。新增图片只有带来新的年龄、姿态、妆造、光照、分辨率或角色外观覆盖时才有价值。
2. **先一次检测，再多人并行比对。** 对同一视频帧的人脸只检测和编码一次，再同时检索全部人物库，避免“每人跑一遍视频”的重复成本和不可比较结果。
3. **任一参考图命中可以召回，不能要求全部命中。** 真实出镜可能只与一个侧脸、年代或角色相近的参考图相似；“所有图都像”会显著漏检。
4. **身份判定基于轨迹和竞争对象，不基于孤立帧。** 连续、同一张脸的多帧支持，以及与第二名对象的分差，通常比某一帧最高分更可靠。
5. **模型分数只产生证据，不替代审核判断。** 人脸检索不决定人物是否敏感，也不决定内容审核结论。

## 3. 人物库与参考图模型

### 3.1 人物对象

一个人物对象包含稳定 ID、名称与别名、分类、启用状态、审核说明，以及一组经过人工身份核验的本地参考素材。任务创建时冻结对象库版本、模型版本与阈值版本，保证结果可复现。

每张参考图保存以下算法元数据，不在审核员工作台展示素材来源：

| 字段 | 说明 |
| --- | --- |
| identity_verified | 身份是否经人工确认 |
| face_embedding | 对齐后人脸特征向量 |
| face_quality | 清晰度、脸部尺寸、曝光、遮挡、姿态的综合质量 |
| appearance_bucket | 年龄阶段、角色造型、姿态、光照、清晰度等外观簇 |
| reference_role | `anchor`（常规泛化）或 `appearance`（特定角色/片中造型） |
| duplicate_cluster | 近重复图所属簇，用于去重和限权 |
| model_version | 产生特征的模型版本 |

`appearance` 图可提高特定媒资或角色的召回，但不能单独作为跨媒资泛化能力的依据；评估报表必须把它与 `anchor` 图分开统计。

### 3.2 参考图准入与淘汰

导入时自动执行：单脸检测、关键点对齐、最小脸尺寸检查、模糊/曝光/遮挡/姿态评分、向量生成和近重复聚类。未通过者进入“待处理”，不能参与检索。

建议准入规则：

- 图中恰好一张可用人脸；检测置信度、脸部尺寸和清晰度达到模型基线要求；
- 身份由人工核验；
- 与已有图高度相似的连拍只保留质量最高的一张；
- 超侧脸、严重遮挡、低照度图可以保留为压力样本，但降低权重，不作为唯一锚点；
- 人物库中不得混入海报插画、多人合影未裁切图或身份不确定图。

推荐每个对象先建设 **3–8 张强参考图**：正面/近正面、半侧脸、不同年代或主要角色造型各至少一类。达到覆盖后新增图片先进入候选池，只有形成新外观簇或提升离线验证指标时才进入在线图库。常规上限可设为 20 张有效原图；更多图片以簇原型保存，而不是无限增加向量数量。

### 3.3 参考图质量权重与原型

第 $i$ 张参考图的质量权重记为 $q_i \in [0,1]$，由图像质量和人工状态共同决定。同一近重复簇的总权重封顶，避免一组连拍主导结果。

对每个外观簇 $C_j$ 建立归一化原型：

$$c_j = \operatorname{norm}\left(\sum_{i \in C_j} q_i r_i\right)$$

其中 $r_i$ 是第 $i$ 张参考图的归一化人脸向量。保留原图向量和簇原型两套表示：原图有利于发现罕见姿态，原型有利于抑制单图偶然误报。

## 4. 本地媒资处理

### 4.1 解码与覆盖

每个文件先进行码流预检，记录时长、分辨率、帧率、音视频流及推荐解码策略。随机 seek 不稳定的格式必须用顺序解码、关键帧索引或转封装后取证；候选截图导出也必须沿用同一策略。结果需要记录实际扫描区间、抽样密度和未覆盖区间。

### 4.2 两阶段采样

1. **粗扫：** 以低成本间隔采样，检测人脸并生成向量；对镜头切换、人物密集和低质量片段可自适应加密。
2. **复扫：** 对粗扫候选的时间窗前后扩展，以更高帧率连续解码，建立短时人脸轨迹并补齐证据帧。

这样将全片计算量集中在疑似片段，也避免仅靠稀疏抽帧错过短暂出镜。

### 4.3 人脸候选与轨迹

每张帧内完成人脸检测、关键点对齐、质量筛选、向量生成。时间相邻且空间位置、外观向量连续的脸框组成轨迹；多人同框时每张脸独立建轨。轨迹关联同时使用位置连续性和人脸特征，不能仅凭时间相近合并。

低质量脸不应直接丢弃：若处于高质量轨迹中，可作为辅助帧；若整段都低质量，输出“数据质量不足”而非负结论。

## 5. 多参考图检索与融合

设候选脸向量为 $e$，人物 $p$ 有参考向量集合 $R_p$ 和原型集合 $C_p$。计算：

$$s_i = e \cdot r_i$$

并得到三个互补分数：

| 分数 | 定义 | 作用 |
| --- | --- | --- |
| 最大分数 $s_{max}$ | $\max_i s_i$ | 对稀有姿态最敏感，用于候选召回 |
| 加权 Top-K $s_{topk}$ | 前 $K$ 个非重复簇分数的质量加权均值 | 抑制单图偶然高分 |
| 原型分数 $s_{proto}$ | $\max_j e \cdot c_j$ | 判断是否接近一个稳定外观簇 |

候选检索先使用：

$$S_{recall}(p,e)=\max(s_{max}, s_{proto})$$

只要达到对象的候选阈值 $T_{recall,p}$，即保留候选。确认分数不是固定公式，而是由已标注验证集为每个对象选择最合适的融合器：`max`、加权 Top-K、原型，或它们的校准组合。当前样本不足时使用按画质桶校准的全局模型加对象偏移，而不是对每个人单独训练复杂分类器。

推荐的确认特征为：

$$x=[s_{max},s_{topk},s_{proto},\Delta,s_{face},s_{track},coverage]$$

其中：

- $\Delta$：第一名人物与第二名不同人物的分差；
- $s_{face}$：当前脸的可用质量；
- $s_{track}$：同一轨迹内高分帧的稳健聚合分数；
- $coverage$：该对象参考图覆盖度，不足时提高人工审核等级而非虚高模型分数。

对 $x$ 采用可解释的校准器（初期为分桶阈值与逻辑回归，样本充足后可比较保序校准），输出确认概率 $P_p$。校准器只用于排序和分流；界面仍应展示关键证据帧、轨迹长度和相近对象，不把概率写成“识别事实”。

## 6. 开放集、冲突与时序归并

人物库不可能覆盖所有出镜者，因此必须是开放集识别。若最高分未达到候选阈值，标为未知人脸；若第一、第二名人物的分差低于对象阈值 $M_p$，标为身份歧义，不强行指定某个人。

同一脸轨迹的事件分数采用高质量帧的稳健聚合，例如取前若干非重复时间点的加权分位数，而不是简单累计所有连拍帧。一个确认事件至少满足：

1. 轨迹内存在达到 $T_{recall,p}$ 的候选帧；
2. 稳健轨迹分数达到 $T_{confirm,p}$；
3. 有足够的时间支持或多帧支持；
4. 与下一候选人物的分差达到 $M_p$，且不存在身份冲突；
5. 证据截图能从原始本地媒资稳定复现。

相邻轨迹只有在身份一致、时间间隔不超过对象配置的合并窗口、且视觉证据无冲突时才能归为同一出镜事件。跨镜头和群像场景应保留多个证据片段，避免将不同人物或不同出镜合并。

## 7. 阈值校准

阈值按对象、画质桶和模型版本管理，至少包括：候选阈值 $T_{recall,p}$、确认阈值 $T_{confirm,p}$、身份分差 $M_p$、最短轨迹支持和事件合并间隔。

校准数据必须包含：目标人物正样本、同片非目标演员、跨媒资人物、相貌或年代接近者、侧脸/遮挡/低清样本以及无人脸或海报类干扰。不得用同一帧的近重复图同时训练和评估，也不得把演员表推断为逐脸真值。

选择策略：先在验证集上固定允许的漏检风险，选出能满足目标召回的最低候选阈值；再以每小时误报事件数、身份混淆率和审核时长选择确认阈值与分差。阈值变更必须产生新版本，并用冻结的回归集复验。

## 8. 评估协议

完整评测分为三层：

| 层级 | 单位 | 指标 |
| --- | --- | --- |
| 人脸检索 | 标注脸 | Top-1/Top-3 召回、未知人脸误接纳、身份混淆 |
| 事件检测 | 人物—时间段 | 事件召回、事件精确率、漏检时长、误报事件/小时 |
| 审核效率 | 审核任务 | 候选压缩比、每有效事件复核时长、人工浏览时长下降 |

至少设置两种隔离切分：

- **参考图切分：** 同一人物的测试脸与参考图不能来自连续帧或近重复图片；
- **媒资切分：** 用未参与阈值调优的影片测试跨片泛化；片中角色参考图和外部锚点图分别报告。

报告必须按人物、影片、年代、分辨率、姿态和解码策略拆分。只报告总准确率会掩盖少数人物的严重漏检或某种文件格式的系统性失败。

## 9. 人工审核与大模型职责

人工审核员在工作台查看：时间段、连续证据帧、同轨迹候选、相近对象、实际覆盖范围，并能确认、驳回、标为未知或质量不足。每一次处置作为阈值校准和对象库治理的标注数据。

大模型不参与人脸身份的最终分数，也不改变候选阈值。它适合在确定性证据之后做三类工作：

1. 归纳同一时间段中来自画面、OCR、ASR、规则库的证据；
2. 按审核规则生成可编辑的复核说明和待确认问题；
3. 发现证据冲突、证据不足或需要补扫的任务。

模型生成内容必须引用结构化证据 ID、时间码和规则版本，不能凭空补充“人物已出现”或“审核已通过”的结论。

## 10. 工程落地顺序

### 第一阶段：可验证候选召回

- 多参考图导入、质检、去重、向量缓存；
- 一次视频扫描同时检索全部人物；
- `max` 候选分数、Top-1/Top-2、分差与覆盖记录；
- 顺序解码兼容、候选复扫、证据截图；
- 候选事件与人工确认闭环。

### 第二阶段：可控降噪

- 外观簇原型、质量加权 Top-K、轨迹级聚合；
- 对象级阈值和难负样本校准；
- 身份歧义队列、混淆报表、回归集。

### 第三阶段：规模化运行

- 向量索引服务、模型/图库/阈值版本化；
- 任务分片和断点续扫；
- 基于审核反馈的周期性离线再校准；
- 在明确达到事件误报与审核效率门槛的低风险场景，才考虑将“已确认”降低为抽检优先级，而非取消人工责任。

## 11. 当前原型的实现约束

当前原型的单参考图分析器只能证明基础链路。下一次实现应将任务输入升级为“人物对象及其有效参考图集合”，对每张检测脸只生成一次 embedding，再输出所有对象的候选排序、融合分数、分差和轨迹事件。单参考图接口可保留为兼容模式，但不得作为多人物生产路径。

在正式宣称准召指标前，每位参与评测的人物应补齐至少三张通过质检、覆盖不同外观簇的本地参考图，并完成脱离演员表和模型分数的盲标。未满足这一条件时，系统只能报告候选链路与代理指标，不能报告正式准确率或召回率。

## 12. 产品准入与稳定性门槛

人物检索能力不能按“模型已接入”整体上线，而应按人物对象、媒资类型和模型版本分别准入。每个对象只可处于以下之一：

| 准入级别 | 使用方式 | 必要条件 |
| --- | --- | --- |
| 实验 | 仅研发观察 | 参考图或盲标不足；不得进入正式任务结果 |
| 候选可用 | 输出待复核线索 | 至少三张通过质检的锚点图；解码覆盖和证据复现通过 |
| 审核优先级可用 | 按置信度排序人工队列 | 冻结验证集上满足候选召回目标，且交叉媒资误报密度低于该对象阈值 |
| 高置信抽检 | 已确认事件优先抽检，不免除人工责任 | 事件级精确率、身份分差、轨迹稳定性和回归集均达到内部审批门槛 |

建议首个试点按“候选可用”上线，待积累盲标后再由业务方设定风险等级对应的数值门槛。对需要降低人工复核密度的对象，可先采用以下保守验收口径：

- 独立影片、独立参考图切分下的候选事件召回率不低于 95%；
- 高置信事件的人工复核精确率不低于 98%，并单列无法判定项；
- 交叉媒资错误事件密度低于每小时 0.1 个，且不存在重复身份混淆模式；
- 每个确认事件可从原始本地媒资稳定复现，任务扫描覆盖率为 100%，或明确列出未覆盖区间；
- 模型、图库、阈值任一升级后，冻结回归集不得出现超过批准上限的回退。

上述数值是保守的起始验收建议，不是脱离业务风险等级的通用法律或审核标准。任何一项未通过时，系统自动降级为“候选可用”或“数据质量不足”，而不是继续输出自动确认。
